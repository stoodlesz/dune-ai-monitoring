# 2026-06-05

Today the project moved from an early research idea into the first version of a working codebase.

The main focus was setting up a foundation for the dataset and preprocessing pipeline. Since this project is about both environmental AI and secure machine learning, the first priority was not to jump straight into model training, but to make sure future imagery can be tracked properly.

The project now has a small Python package under `src/dune_ai_monitoring/`. It includes preprocessing helpers for image tiling, NDVI/NDWI calculations, and psammosere stage label validation. These are the first reusable building blocks for turning satellite or aerial imagery into model-ready data.

A dataset manifest format was also added. This is important because each image or tile should have a clear record of where it came from, when and where it was captured, which sensor and bands were used, how it was labelled, and whether the file can be verified with a SHA-256 hash. This connects the ecological research side of the project with the cybersecurity/provenance side.

The repo now includes:

- a project package with preprocessing and dataset utilities
- a manifest template at `data/metadata/example_manifest.csv`
- documentation for the manifest format in `docs/dataset_manifest.md`
- tests covering the first preprocessing and dataset functions
- updated setup instructions in the README

Later in the day, the manifest work was extended into a small command-line tool: `dune-manifest-add`. This command takes a local image file, records the important source and label metadata, computes the file's SHA-256 hash automatically, and writes everything into a manifest CSV.

In practical terms, this means the project now has a repeatable way to register source imagery before it becomes training data. That is a useful bridge between the environmental side of the project and the secure ML side: every future image can have a record of origin, label confidence, sensor/band details, and file integrity.

The next layer was started with `dune-pc-download`, a command for searching Microsoft Planetary Computer's STAC API for Sentinel-2 L2A imagery. It can pick the least-cloudy matching item, download a chosen asset, and register the downloaded file in the manifest. This is the first step toward automatically bringing real satellite imagery into the project instead of only documenting how imagery should be stored.

The command was then tried against Dune du Pilat in France. A Sentinel-2 item from 2025-07-11 was selected with very low cloud cover, and a small rendered preview image was downloaded locally for inspection. The image itself is kept out of Git, but the metadata record and a readable report were added under `data/metadata/`.

The Dune du Pilat report adds context that the image alone does not provide: source item ID, capture date, cloud cover, SHA-256 hash, bounding box, approximate search-box area, and a reminder that this is not yet a measured sand-dune area. Measuring dune area will require a later image analysis step that separates sand, vegetation, water, and built-up pixels.

The README was also updated with a clearer file breakdown and organisational structure, so the repository is easier to understand when returning to it later.

At this stage, the project can search for real Sentinel-2 imagery, download a preview asset, register it in a provenance-aware manifest, and generate a human-readable image report. It does not yet train a model or calculate the actual area of sand dunes.

Next useful step: build preprocessing outputs from a recorded source image, then start exploring how to separate sand, vegetation, water, and urban pixels.
